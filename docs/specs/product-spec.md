# Product Specification

## Working product name

**Navo** (company: Halden, fictional). Tagline: "AI That Handles Onboarding".

Brand confirmed for the prototype.

## Product positioning

> An AI agent that owns the employee onboarding journey instead of handing the employee another checklist.

## Core promise

The employee should be able to ask:

> "What do I need to care about right now?"

and get a concise answer while the agent handles the underlying coordination.

## Primary user

New employee from offer acceptance through first week.

## Secondary user

Internal onboarding owner such as HR/onboarding operations.

## Core employee experience

### Home
Shows:
- current onboarding state
- what needs employee attention
- what the agent is handling
- waiting items
- current risks

### Journey
Shows the full onboarding lifecycle:
Offer → Pre-joining → Day 1 → Week 1

### Agent Activity
Shows meaningful actions the agent has taken, for example:
- detected dependency
- evaluated risk
- contacted HR
- created IT request
- updated state

### Ask
Natural-language interaction grounded in synthetic company policies and employee context.

## Core principle: attention over information

The employee should not see the entire enterprise workflow by default.

The UI should compress complexity into:
- Need you
- Agent handling
- Waiting on others
- At risk

## Product differentiator

The agent is judged by what it does, not by how much AI copy appears in the interface.

Example:

Employee ID delayed
→ agent detects laptop dependency
→ agent detects Day-1 risk
→ agent contacts HR
→ HR resolves dependency
→ agent creates laptop request
→ onboarding state updates
→ employee receives concise update

## Out of scope

- Full HRIS replacement
- Payroll system
- Production IAM
- Real corporate system integrations
- Full enterprise knowledge platform
- Broad employee lifecycle coverage
- Multiple unrelated AI agents
- Complex infrastructure for its own sake
