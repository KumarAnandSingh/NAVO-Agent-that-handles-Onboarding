# Competition Evaluation Checklist

The instruction email states that projects will be evaluated on:

## 1. Innovation & Creativity

Questions:
- Is the concept meaningfully different from a normal onboarding portal?
- Does AI materially change the workflow?
- Is the agent proactive rather than merely conversational?
- Is there a clear product thesis?

## 2. Technical Complexity

Look for credible depth such as:
- real LLM integration
- policy retrieval / RAG
- structured state management
- dependency reasoning
- tool calling
- orchestration
- event-driven behaviour
- guardrails / approvals

Avoid complexity that does not create product value.

## 3. Code Quality

Required qualities:
- readability
- maintainability
- strong typing
- clean module boundaries
- limited duplication
- sensible abstractions
- predictable error handling

## 4. Testing & Reliability

The email explicitly requires comprehensive unit tests.

Also include:
- integration tests for agent/tool/state behaviour
- E2E tests for the golden path
- failure-path testing

## 5. Documentation

Technical design should clearly explain:
- project overview
- selected track
- architecture and flows
- setup
- deployment
- code structure
- assumptions
- limitations

## 6. Demo Quality

The video should clearly show:
- business problem
- user experience
- AI intervention
- agent activity
- state change
- business value

## Mandatory submission checklist

- [ ] Fully functional project
- [ ] Personal GitHub repository
- [ ] Technical design document
- [ ] Architecture/flow diagrams
- [ ] Setup/deployment instructions
- [ ] Code explanations and assumptions
- [ ] YouTube demo video
- [ ] Comprehensive unit tests
- [ ] Demo is reproducible
- [ ] Synthetic/mock data only
